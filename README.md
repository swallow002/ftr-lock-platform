# 智能 F-TR 锁管控平台

面向现场汇报和答辩的工业科技风演示网站。所有设备、受力、位置和操作均为模拟数据；登录页是展示入口。

GitHub仓库：[swallow002/ftr-lock-platform](https://github.com/swallow002/ftr-lock-platform)

网站发布目标：[打开演示网站](https://swallow002.github.io/ftr-lock-platform/)。部署进度见仓库Actions。

## 本地运行

需要 Node.js 22.12+ 与 npm。

```bash
npm ci
npm run dev
```

打开终端显示的本地网址，点击“登录”。默认进入装车指引。

Windows可直接双击“启动演示.cmd”。双击“构建网站.cmd”可生成发布文件；两个脚本会优先使用本机Codex附带的较新Node运行时，再回退到系统Node，避免本机旧版Node 24.12.0的异常退出。

```bash
npm test
npm run build
npm run preview
```

## 六个模块

- **装车指引**：30秒，下降2.6cm → 右旋0.34° → 下降3.5cm → 左旋0.34° → 吊钩松开。松钩提示2秒后清除。
- **途中货检**：全系统440把锁，436正常、4异常；异常车辆四把锁作为一组待检查，受力约72/73/53/53kN。
- **换轨吊装**：卸车30秒，最后上升5m；随后跨轨移动5秒并停止。切换装车入口后独立开始30秒装车，首次下降2.7cm。
- **途中监管**：440在线、0异常；车辆主画面加真实地图，模拟轨迹、经纬度、速度和受力随演示时间更新。
- **卸车指引**：30秒，包含第一把锁卡阻与左旋0.2°解除过程；最后上升5cm。
- **设备管理**：当前区域58把设备，55正常在线、3离线异常；支持编号、车号搜索、状态筛选与地图点选。

装卸可开始、暂停/继续、重播；切换车辆或模块恢复初始状态。每个模块是独立案例，异常数量不跨模块延续。全局固定生成110辆车、440把锁，当前演示列车取前13辆车；设备管理区域从全系统中取58把，不限定为这13辆车。

## 地图

Leaflet 1.9.4 + OpenStreetMap真实底图，需要联网加载。网站其余脚本和图形均随构建打包。点位、路线均为模拟；离线设备展示最后已知位置。底图不可用时仍显示模拟点位并保留搜索、列表和详情。

保留OpenStreetMap来源署名，按需加载当前地图视野，不提供离线下载或批量预取。

## 发布到 GitHub Pages

1. 在你的GitHub下创建公开仓库 `ftr-lock-platform`。
2. 将本目录中的网站源代码推送到仓库 `main` 分支（不要上传 `node_modules`）。
3. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
4. 已包含工作流 `.github/workflows/deploy.yml`，推送后自动测试、构建并发布。
5. 发布成功后，网址为 `https://你的用户名.github.io/ftr-lock-platform/`。以GitHub部署页面实际返回的网址为准。

使用相对资源路径，无需为项目仓库另改资源前缀。模块通过站内状态切换，刷新任意页面都会返回模拟登录页，不依赖服务器路由。

## 调整数据和流程

- `src/data.ts`：设备、车辆、流程阶段、关键数值、地图轨迹。
- `src/usePlayback.ts`：统一演示时钟，驱动数值、阶段和二维动画。
- `src/Scene.tsx`：集装箱、锁具、双轨道SVG示意。
- `src/App.tsx`：六个模块及交互。
- `src/styles.css`：工业科技视觉及大屏、小屏适配。

当前主界面优先适配1920×1080和1366×768，小屏可基本浏览与操作。原始PPT位于网站目录外，不随网站代码发布。
